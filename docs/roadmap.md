# 実装ロードマップ

作成: 2026-08-13 ／ 最終更新: 2026-08-13（カメラ先行へ順序変更）

原則: **企画を殺しうるリスクから潰す。測ってから決める。**
各マイルストーンに「何が確認できたら次へ進むか」を書く。数値の合格ラインは
実測開始時に本書へ記入してから測る（測った後に基準を動かさないため）。

実測環境: MacBook Pro 16" 2021（M1 Pro / 16GB, macOS 26.5.2）＋ 手持ちのiPhone/iPad、同一Wi-Fi。

---

## なぜカメラモードが先か（順序の根拠）

当初はM1にMultipeerConnectivityの実測を置いていた。**変更した理由は、
[architecture.md](architecture.md) §1-3 で映像と解析を分離した時点で、MPCが
企画を殺しうるリスクではなくなったから。** MPCが不成立でも映像が低fpsに退化するだけで、
案内の品質は落ちない。

**企画を本当に殺しうるのは「AIが画面を見て有用な案内を返せるか」**であり、これは
カメラモードなら Macコンパニオン・MPC・ペアリングUX を一切作らずに検証できる。
さらにそこで作るもの — APIサーバー、オーバーレイ描画、座標系、対話UI — は
**ミラーモードでもそのまま使う背骨**であり、ミラーは後から「画像の入手元を差し替える」
だけになる。

## M0. プロジェクトの器 ✅ 着手済み

- リポジトリ構成: `ios/`（Xcodeプロジェクト）、`server/`（APIサーバー）、`mac/`（後述M4で追加）
- bundle ID採番。Debug/Releaseで正体（bundle ID＋アプリ名）を分ける
  （[lessons-from-app-mac.md](lessons-from-app-mac.md) §7）
- `POST /api/analyze` の最小実装（Claude・SSE・ベータトークン検証）

**完了条件**: iOSアプリが実機で起動し、サーバーがローカルで起動する。

## M1. カメラモードのエンドツーエンド ⚠️ 企画最大のリスクはここ

- カメラで画面を撮る → `/api/analyze` → ハイライト＋解説がその静止画上に出る
- 正規化座標→表示ポイント変換（**アスペクト比維持のレターボックス補正を必ず挟む**。
  lessons §6）
- **開始前に合格ラインをここに記入する**（例: 実際のアプリ画面10枚で、
  「押すべき場所」を正しく指せた割合がN割以上）

**完了条件**: 手元の実際の画面（Mac、券売機、他人のPCなど）を撮って、
**汎用チャットAIにスクショを貼るより有用な案内が返る**ことを自分で確認できる。
ここが通らなければ、ミラーリングを作る意味がない。

## M2. 対話とチュートリアル体験

- テキスト質問、対話履歴（turns）、ストリーミング表示
- 「次はここ→できたら次はここ」のステップ案内（撮り直しによる手動トリガーから始める）
- 枠が出ない3値（未指定／置けず／描画済み）のUI区別

**完了条件**: 実タスクを最初から最後まで案内し切れる。

## M3. コンテキストパック（差別化の実証）

- サーバー側に手置きのパック＋iOS側の選択UI＋**適用中パックの常時表示**
- 実在の1システム（自分の業務ツール1つ）でパック有無の案内品質を比較する

**完了条件**: パック有りの案内が汎用案内より明確に良い実例が1つ以上ある。
**これがB2Bピッチの弾になる。** ここまでMacは1行も書いていない。

## M4. Macコンパニオンとミラーリング（MPC実測）

- `mac/` にBroadcasterを作る。ScreenCaptureKit → H.264 → MultipeerConnectivity
- **遅延・フレーム落ち・安定性を数値で出す**。1080p30を基準にfps・解像度を振る
- `.unreliable` ＋フレーム破棄方針、ローカルネットワーク権限、ペアリングUX
- **開始前に合格ラインをここに記入する**（未達なら低fpsプレビュー構成へ切替）
- iOS側は `AVSampleBufferDisplayLayer` を追加し、**画像の入手元をカメラから差し替えるだけ**
  （解析経路・オーバーレイ・対話はM1〜M3で完成済み）

**完了条件**: 「Macの画面をiPadで見て、タップしたら正しい場所に枠と説明が出る」。
**この結果が悪くても企画は死なない**（architecture.md §1-3）。

## M5. AX候補による接地（精度の底上げ）

- Macコンパニオンが Accessibility で操作候補を走査し、フレームと一緒に送る
- iOSは候補をそのまま `/api/analyze` の `source.candidates` へ中継
- モデルには**候補IDを選ばせる**（座標を創作させない。lessons §4）

**完了条件**: ミラーモードのハイライト位置がM4より明確に安定する。

## M6. ベータ配布

- TestFlight配布。ペアリングUX・切断時表示・プライバシーポリシーを揃える
- サーバーのレート制限・トークン失効を運用可能にする

**完了条件**: 身内以外のベータユーザーが自力でセットアップして使える。
