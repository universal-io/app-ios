# Macコンパニオン（Broadcaster）

Macの画面を取得してiOSへ送る側。**サーバーとは通信しない**
（APIクライアントはiOSアプリだけ。[../docs/architecture.md](../docs/architecture.md) §1）。

**状態: M4の測定用CLIのみ。** ScreenCaptureKitがフレームを出せるかを測る段階で、
まだ送信もUIも無い。

## なぜアプリではなくCLIか

M4で最初に確かめるのは「フレームが必要なレートで取れて、必要なサイズで届くか」で、
その答えは端末に出る数字である。ウインドウもメニューバーも無い方が、
**UIの問題を伝送の問題と取り違えずに済む**。アプリの殻は、伝送に投資する価値が
あると測定が言ってから作る。

## 動かす

```bash
cd mac
swift build
./.build/debug/Broadcaster --seconds 5 --fps 30
```

| オプション | 意味 |
|---|---|
| `--seconds N` | 計測時間（既定5） |
| `--fps N` | 要求フレームレート（既定30） |
| `--pixels` | 論理解像度ではなくRetina生ピクセルで取得する |

既定は**論理解像度**（1ポイント=1ピクセル）。解析に送る画像はこれを基準にする
— Retina生ピクセルはトークンの無駄で、逆に落としすぎると数字を静かに誤読する
（[../docs/lessons-from-app-mac.md](../docs/lessons-from-app-mac.md) §3）。

## 🔴 画面収録の許可（最初に必ず当たる）

初回は**必ず失敗する**。macOSは画面収録の許可を求めるまで拒否を返す:

```
capture failed: ユーザがアプリケーション、ウインドウ、ディスプレイ取り込みのTCCを拒否しました
```

**許可はこのCLIではなく、CLIを起動したプログラムに紐づく。** ターミナルから
実行したならターミナルが対象になる。

1. システム設定 → プライバシーとセキュリティ → 画面収録とシステムオーディオ収録
2. 実行に使っているターミナル（Terminal.app / iTerm / VS Code など）を有効にする
3. **そのターミナルを再起動する**（許可は起動時に読まれる）
4. もう一度 `./.build/debug/Broadcaster` を実行する

**エージェント経由のシェルからは許可ダイアログを出せない**ので、この測定だけは
人がターミナルで走らせる必要がある。
